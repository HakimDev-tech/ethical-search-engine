# V0.2 — Secure Crawler Acceptance Criteria

- Document ID: ESE-V02-AC-001
- Version: 1.0
- Status: Proposed; all mandatory criteria require evidence before acceptance

A criterion passes only when implementation and automated tests demonstrate the behavior. Documentation alone is insufficient.

## A. Scope and architecture

### V2-AC-001 — Crate topology
- [ ] Exactly one new package, `ese-crawler`, exists at `crates/crawler`.
- [ ] It is a library crate with real functionality.
- [ ] No empty placeholder crate, binary, microservice or persistence service is added.
- [ ] Internal modules match the responsibilities in `V0.2_CRAWLER_ARCHITECTURE.md`.

### V2-AC-002 — Dependency direction
- [ ] `ese-domain` remains free of HTTP, URL, DNS and async-runtime dependencies.
- [ ] `ese-crawler` does not force async dependencies into domain/config/observability.
- [ ] No circular workspace dependency exists.
- [ ] No dependency is added solely for V0.3 or later.

### V2-AC-003 — Scope discipline
- [ ] No link extraction, recursive crawl, sitemap discovery or persistent frontier is implemented.
- [ ] No HTML extraction, deduplication, indexing, BM25, ERE or ethical classifier is represented as implemented.
- [ ] No browser, proxy, cookie, authentication or CAPTCHA-bypass capability exists.
- [ ] README and docs clearly distinguish fetched bytes from indexed/approved documents.

## B. URL validation

### V2-AC-004 — Standards-based parsing
- [ ] URL parsing uses the approved URL library.
- [ ] URL length is limited to 8,192 bytes before expensive processing.
- [ ] HTTP and HTTPS are the only accepted schemes.
- [ ] Hostname is present and valid.
- [ ] Userinfo is rejected.
- [ ] Only HTTP 80 and HTTPS 443 are accepted.
- [ ] Fragments are removed and queries are preserved.
- [ ] Host and default-port canonicalization are tested.
- [ ] Local-use suffixes, single-label hosts, malformed hosts and IPv6 zone identifiers are rejected.
- [ ] Parser edge cases include Unicode/IDNA and percent encoding.

### V2-AC-005 — No unsafe URL bypass
- [ ] `file:`, `ftp:`, `data:`, `javascript:`, custom schemes and malformed authorities are rejected.
- [ ] A caller cannot override Host, Authorization, Cookie or other restricted headers.
- [ ] Invalid URLs fail before DNS or HTTP transport is invoked.

## C. Destination and SSRF defense

### V2-AC-006 — Address classification
- [ ] IPv4 private, loopback, link-local, unspecified, shared, multicast, broadcast, documentation, benchmarking and reserved ranges are denied.
- [ ] IPv6 loopback, unspecified, unique-local, link-local, multicast, documentation, transition and other special-purpose ranges are denied.
- [ ] IPv4-mapped IPv6 is normalized before classification.
- [ ] Only globally routable unicast destinations are allowed.
- [ ] CIDR policy is documented with authoritative registry/RFC provenance.
- [ ] Boundary tests cover every configured CIDR block.

### V2-AC-007 — DNS validation
- [ ] DNS resolution is behind an injectable asynchronous interface.
- [ ] Mixed public/private answers result in only public addresses being retained.
- [ ] An empty safe-address set rejects the request.
- [ ] DNS errors fail closed.
- [ ] DNS answer data is not logged in full.

### V2-AC-008 — DNS pinning
- [ ] The HTTP connector is pinned to the filtered address set for the requested host.
- [ ] The original hostname is preserved for TLS SNI and HTTP authority.
- [ ] The HTTP client cannot perform an uncontrolled second DNS lookup.
- [ ] A fresh resolution is used for each new fetch operation.
- [ ] Tests prove unsafe answers never reach the transport.
- [ ] Infrastructure egress restrictions are documented as required defense in depth for production.

## D. HTTP transport

### V2-AC-009 — Transport hardening
- [ ] TLS certificate and hostname validation remain enabled.
- [ ] Ambient proxy configuration is disabled.
- [ ] Cookies and cookie storage are disabled.
- [ ] Redirects are disabled.
- [ ] GET is the only supported method.
- [ ] No caller-controlled Host, Authorization or Cookie header is accepted.
- [ ] User-Agent identifies ESEBot and links to the project.
- [ ] HTTP/1.1 is the V0.2 baseline; HTTP/2 is not enabled without review.

### V2-AC-010 — Redirect safety
- [ ] A 3xx response is returned as a typed non-success outcome.
- [ ] Location is treated as untrusted data.
- [ ] No second request is made after a redirect response.
- [ ] Redirect tests cover external, private-IP and scheme-changing Location values.

### V2-AC-011 — Timeouts and status
- [ ] Connect timeout is at most 5 seconds.
- [ ] Total request timeout is at most 15 seconds.
- [ ] Only HTTP 200 is accepted as a successful page response.
- [ ] Other statuses return typed outcomes.
- [ ] Automatic retries are disabled.

### V2-AC-012 — Bounded body
- [ ] Page body maximum is 5 MiB.
- [ ] robots body maximum is 512 KiB.
- [ ] Content-Length is pre-checked when available.
- [ ] Streamed byte counting remains authoritative.
- [ ] Reading stops immediately when the limit is exceeded.
- [ ] A response without Content-Length is still bounded.
- [ ] Body-size overflow is a typed failure and does not retain the oversized body.

### V2-AC-013 — Content policy
- [ ] Only text/html and application/xhtml+xml are accepted for page fetch.
- [ ] Only identity content encoding is accepted.
- [ ] Compression features are disabled in the client.
- [ ] PDF, image, archive, binary and unsupported media are rejected.
- [ ] Content-type parsing is robust to case and parameters.

## E. robots.txt

### V2-AC-014 — Robots prerequisite
- [ ] No page content request occurs before robots policy is evaluated.
- [ ] robots request uses the same URL/DNS/IP/TLS/timeout/size protections.
- [ ] robots cache is keyed by exact origin, including scheme and port.

### V2-AC-015 — RFC 9309 matching
- [ ] ESEBot product-token group selection works.
- [ ] Wildcard fallback works.
- [ ] Multiple equally specific groups are combined as required.
- [ ] Allow and Disallow matching work.
- [ ] Longest matching rule wins.
- [ ] Allow wins equal-length ties.
- [ ] Percent-encoding and path matching are tested.
- [ ] Comments, blank lines and UTF-8 are handled.
- [ ] The selected parser dependency has documented maintenance, license, MSRV and conformance evidence.

### V2-AC-016 — Robots failure matrix
- [ ] 2xx valid body is parsed.
- [ ] 404/410 is treated as no published file.
- [ ] 401/403 denies.
- [ ] Other 4xx denies.
- [ ] 3xx is not followed and denies.
- [ ] 5xx denies.
- [ ] Timeout, DNS, TLS, invalid UTF-8, oversized body and parser error deny.
- [ ] No failure mode silently becomes an allow decision.

### V2-AC-017 — Robots cache
- [ ] Successful policy and 404/410 absence cache for no more than 24 hours.
- [ ] Failure/denial cache lasts no more than 5 minutes.
- [ ] Expired entries are revalidated.
- [ ] Cache behavior is deterministic under tests.
- [ ] Cache does not grow without a bounded eviction strategy.

## F. Politeness and resource management

### V2-AC-018 — Global and per-origin limits
- [ ] Default global in-flight request limit is 8 and cannot be configured above 8.
- [ ] Per-origin in-flight request limit is exactly 1.
- [ ] Origin key includes scheme, host and effective port.
- [ ] Concurrent same-origin requests are serialized.
- [ ] Different origins may proceed concurrently within the global limit.

### V2-AC-019 — Request spacing
- [ ] Default minimum inter-request spacing is 1 second.
- [ ] Configuration may increase but not lower the hard floor.
- [ ] Cancellation and errors do not corrupt the next-eligible timestamp.
- [ ] Crawl-delay extension is either correctly enforced or rejected/deferred; it is never silently ignored when valid and supported.

### V2-AC-020 — Retry-After and cooldown
- [ ] 429 and 503 do not trigger automatic retry.
- [ ] Valid Retry-After creates an origin cooldown.
- [ ] Invalid/missing Retry-After uses a conservative fallback.
- [ ] A deferred result is returned to the caller.
- [ ] Cooldown is applied to all paths for that origin.

### V2-AC-021 — Cancellation safety
- [ ] Global and origin permits are released after success, error, timeout and cancellation.
- [ ] Tests demonstrate no leaked permit or permanent origin lock.

## G. Privacy and diagnostics

### V2-AC-022 — URL and content redaction
- [ ] Raw query strings and fragments never appear in ordinary logs.
- [ ] Userinfo never appears in logs or errors.
- [ ] Response bodies and arbitrary headers are never logged.
- [ ] Credentials, cookies and personal data are not emitted.
- [ ] Redaction happens before tracing event construction.
- [ ] Debug logging follows the same rules.

### V2-AC-023 — Typed outcomes
- [ ] URL rejection, destination rejection, robots denial, deferral, transport failure, status failure, media failure, size failure and success are distinguishable.
- [ ] Display strings do not contain raw URLs or response content.
- [ ] Internal diagnostic sources remain available without being emitted by default.

## H. Quality, CI and release

### V2-AC-024 — Deterministic test suite
- [ ] DNS and HTTP are injectable.
- [ ] Tests do not require public DNS or Internet access.
- [ ] URL, IP, robots, redirects, limits, politeness, cancellation and redaction are covered.
- [ ] Test fixtures are explicit and version-controlled where appropriate.

### V2-AC-025 — Dependency governance
- [ ] Every new direct dependency has a documented purpose.
- [ ] New dependencies pass cargo-deny advisory, license, source and ban checks.
- [ ] Direct dependency features are explicitly minimized.
- [ ] MSRV 1.85.0 compatibility is verified or the MSRV change is separately approved.
- [ ] No unreviewed robots parser dependency is added.

### V2-AC-026 — CI parity
- [ ] Formatting, metadata, check, build, Clippy, tests, docs, cargo-deny and MSRV checks pass.
- [ ] Architecture/dependency boundary checks are updated.
- [ ] CI executes the documented commands with locked dependency resolution.

### V2-AC-027 — Documentation
- [ ] Product spec identifies V0.2 scope and non-goals.
- [ ] Architecture matches the actual crate/module layout.
- [ ] Technical decisions record all selected dependencies and security trade-offs.
- [ ] README describes how to run offline tests and accurately states what the crawler does not do.
- [ ] No document claims crawler functionality before implementation is merged.

### V2-AC-028 — Final release gate
- [ ] All mandatory criteria V2-AC-001 through V2-AC-027 pass.
- [ ] CI succeeds on the final implementation commit.
- [ ] No unresolved critical/high security advisory remains.
- [ ] SSRF, DNS pinning, robots and bounded-streaming evidence is included in the validation report.
- [ ] Scope exclusions and residual risks are documented.
- [ ] PR remains unmerged until explicit owner approval.

## Required validation report

Record commit SHA, toolchain, host platform, dependency inventory, MSRV result, CI links, test counts, cargo-deny result, security test evidence, waived criteria and final ACCEPTED/REJECTED decision.
