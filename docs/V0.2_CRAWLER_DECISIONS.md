# V0.2 — Crawler Technical Decisions

- Document ID: ESE-V02-ADR-001
- Version: 1.0
- Status: Proposed decisions for implementation review

This document supplements `docs/TECHNICAL_DECISIONS.md`. It does not silently supersede existing ADRs.

## ADR-V02-001 — One crawler library crate

**Decision:** Add exactly one crate, `ese-crawler`, at `crates/crawler`.

**Context:** V0.2 needs URL policy, DNS, transport, robots and politeness. These concerns are cohesive parts of one crawler capability.

**Alternatives:** Separate Cargo crates for URL, DNS, robots and transport; a crawler binary; a standalone crawler service.

**Rationale:** Internal modules provide sufficient boundaries. More crates or a service would add dependency and deployment complexity before reuse or independent release is demonstrated.

**Consequences:** No empty packages, binary or microservice is added. Modules may be extracted later only with evidence.

## ADR-V02-002 — Asynchronous I/O with Tokio

**Decision:** Introduce Tokio only in `ese-crawler`, with the minimum features required for runtime, networking, synchronization and time.

**Rationale:** DNS lookup, HTTP I/O, cancellation and bounded concurrency are asynchronous operations. The existing domain crate remains synchronous and runtime-independent.

**Consequences:** CPU-heavy parsing must not execute on async worker threads in future releases. The crawler API documents its async contract.

## ADR-V02-003 — Reqwest with Rustls and a restricted feature set

**Decision:** Use Reqwest for HTTP transport with Rustls, streaming support and no cookie, compression or ambient proxy behavior.

**Rationale:** It provides a maintained Rust HTTP client while allowing response streaming, explicit TLS and request policy.

**Consequences:** Exact versions and features are selected only after MSRV, license, advisory and API review. Automatic redirects are disabled. HTTP/2 is deferred. TLS verification must never be disabled.

## ADR-V02-004 — Standards-based URL parsing

**Decision:** Use the `url` crate for URL parsing and canonicalization.

**Rationale:** URL parsing has complex normalization, IDNA, percent-encoding and authority rules; ad hoc string parsing is unsafe.

**Consequences:** Product restrictions are layered on top of parsed URL values. Query strings are preserved for the request but redacted from logs.

## ADR-V02-005 — Explicit public-address policy and DNS pinning

**Decision:** Resolve each host through an injectable resolver, filter the result against a documented IPv4/IPv6 special-purpose range policy, and pin the HTTP client to the filtered addresses for that fetch.

**Rationale:** Checking a DNS result and then allowing the HTTP client to resolve again leaves a DNS-rebinding/TOCTOU gap.

**Consequences:** The address policy needs provenance, boundary tests and maintenance. Mixed DNS responses may use only approved public addresses. Redirects remain disabled. Production egress firewalling is defense in depth.

## ADR-V02-006 — No automatic redirects

**Decision:** Do not follow redirects in V0.2, including page redirects and robots redirects.

**Rationale:** Every redirect creates a new untrusted destination that must undergo complete URL, DNS, address and robots validation. Automatic redirect behavior would bypass the intended trust boundary.

**Consequences:** 3xx is a typed non-success outcome. Safe manual redirect support may be considered later as a separate decision with a low hop limit and full revalidation per hop.

## ADR-V02-007 — Conservative robots enforcement

**Decision:** Require robots evaluation before page fetch. Treat 404/410 as no published robots file; deny crawling on 401/403, other 4xx, 3xx, 5xx, timeout, DNS/TLS failure, oversized body, invalid encoding or parser failure.

**Rationale:** ESE chooses not to interpret inability to read a site's crawl policy as permission to fetch.

**Consequences:** This is stricter than some interpretations or implementations of the Robots Exclusion Protocol. The exact behavior is documented and tested. robots.txt remains a crawl convention, not legal authorization.

## ADR-V02-008 — Bounded in-memory crawl state

**Decision:** Keep robots cache, host gates and cooldowns in memory for V0.2. No database, persistent frontier or distributed scheduler.

**Rationale:** The first release must prove safe single-process acquisition before introducing persistence or distributed coordination.

**Consequences:** Restart resets crawl history and cache. Production multi-process crawling requires a separate design.

## ADR-V02-009 — Strict HTML-only bounded acquisition

**Decision:** Accept only `text/html` and `application/xhtml+xml` page responses, identity content encoding and a maximum 5 MiB body. robots.txt has a 512 KiB limit.

**Rationale:** The release is an acquisition foundation, not a general downloader. Disabling compression avoids decompression-bomb complexity at this stage.

**Consequences:** PDFs, images, archives, compressed responses and arbitrary binary data are rejected. Extraction is deferred to V0.3.

## ADR-V02-010 — No recursive discovery or automatic retries

**Decision:** V0.2 accepts explicit seed URLs only and performs at most one page fetch per operation. It does not extract links, persist a frontier or retry automatically.

**Rationale:** URL discovery creates an unbounded state space and amplifies security, politeness and deduplication concerns. Retries can also violate host policy if not centrally scheduled.

**Consequences:** A caller may schedule a later attempt using the returned typed outcome and cooldown. Recursive crawl design is deferred until bounded frontier and duplicate controls are specified.

## ADR-V02-011 — Privacy-preserving crawler telemetry

**Decision:** Log stable reason codes and bounded operational metadata, not raw URLs, query strings, headers or page content.

**Rationale:** URLs frequently contain personal identifiers, access tokens or search-like user data. Response bodies can contain arbitrary personal data.

**Consequences:** Redaction occurs before tracing event construction. Debug logs are subject to the same rules.

## ADR-V02-012 — Dependency governance

**Decision:** Keep the direct dependency set small and audit every selected parser and networking dependency for MSRV, license, maintenance, advisories and enabled features.

**Consequences:** No robots parser crate is pre-approved by name in this specification. The implementation phase must record the selected parser and evidence before adding it. Existing cargo-deny policy remains mandatory.

## Open questions deliberately deferred

- Persistent frontier and crawl history.
- Cross-process politeness and distributed scheduling.
- Safe redirect support.
- Sitemap discovery.
- Crawl-delay interoperability beyond the documented extension.
- Browser rendering and JavaScript.
- Content extraction, canonical links and deduplication.
- Legal/terms-of-service registry and domain-level permissions.

These are not blockers for V0.2's bounded single-process scope.
